# 唱机 — Local Music Player

[English](README.md)

本地 FLAC 播放器，带本机推荐。扫描电脑上的文件夹，在浏览器里播放，并根据完播 / 跳过学习口味，听歌记录不会上传。

界面是中文。音频文件和播放历史**不在**这个仓库里。

## 功能

- 读取本地文件夹里的 FLAC（内置解析器：Vorbis 标签、音轨 / 碟号、ReplayGain、内嵌封面）；MP3 / M4A / OGG / Opus 由 `music-metadata` 解析
- 封面来自内嵌图片或同目录的 `cover.jpg` / `folder.jpg`；同名 `.lrc` 显示滚动歌词
- 单曲循环、歌手循环、随机、全部循环，以及由模型选下一首的**智能推荐**模式
- 从歌手、专辑、歌单或搜索结果里点播，就在**这个列表**里往下播；右键任意歌曲可以「下一首播放」「加入队列」、加入歌单、喜欢 / 不喜欢
- 歌单、「我喜欢」和「听歌统计」页面
- 按歌名、歌手、专辑搜索，也支持拼音（`zjl`、`zhoujielun`）
- 支持键盘媒体键、耳机线控和 macOS「正在播放」（Media Session API）
- 刷新页面后接着上次的歌、进度和队列
- 可选 ReplayGain 音量均衡
- 自动监听曲库目录，新增、移动、改标签的文件不用手动重新扫描
- **为你推荐**：逻辑回归 + Item2Vec + 连听关系，全部在本机训练
- 可选 macOS 程序坞图标

## 环境

- Node.js 20.19+
- 一个音频文件夹（默认 `~/Desktop/music-resources`）
- 只有需要程序坞图标时才要求 macOS；Linux / Windows 用 `npm run dev` / `npm start` 即可

## 开始

```bash
npm install
npm run dev
```

浏览器打开 [http://localhost:5173](http://localhost:5173)。生产模式（打包界面 + API）是 [http://localhost:8787](http://localhost:8787)：

```bash
npm run preview
```

曲库目录可改 `config.json` 里的 `musicDir`，或启动时设置环境变量：

```bash
MUSIC_DIR="/path/to/music" npm run dev
```

在 macOS 上生成本地 **唱机.app**（桌面和 `~/Applications`）：

```bash
npm run install-app
```

第一次会打包界面并打开浏览器；从程序坞退出会关掉后台服务。不要把 `唱机.app` 提交进 Git，它会写入你这台机器上的项目路径。启动器只在 `dist/` 不存在时才打包界面，所以拉取新代码后要先执行 `npm install && npm run build` 再重启 app。

## 播放

- **单曲循环** / **歌手循环** / **随机播放** / **全部循环** / **智能推荐**：点播放条右侧的模式按钮切换
- **快进 / 快退 10 秒**：播放键两边的箭头，或键盘 `←` / `→`（Shift 为 30 秒）
- **倍速**：`0.5x`–`2x`，点击循环，悬停或聚焦可选精确值
- 进度条可拖动，也能用键盘操作；音量滑杆在右下角
- 👎 标记「不喜欢」：立刻跳过，之后少推荐这类歌
- 右侧面板可在「即将播放」和「歌词」之间切换（点歌词跳到那一句）
- 播放失败的歌会自动跳过，连续三首失败就停下

## 数据文件

都在 `data/` 下（已被 gitignore）：

| 文件 | 内容 |
| --- | --- |
| `listens.json` | 听歌记录（最多 10000 条）、喜欢、不喜欢 |
| `playlists.json` | 歌单 |
| `library-cache.json` | 按路径、大小、修改时间缓存的标签，重新扫描只读有变化的文件 |

写入是原子的（先写临时文件再改名）。文件损坏时会被改名为 `*.corrupt-<时间>.json` 保留下来，不会被覆盖。

歌曲 ID 取自 FLAC STREAMINFO 里的音频 MD5（其他格式用曲库内的相对路径），所以改名、移动、改标签都不会丢记录。旧版本用绝对路径生成的 ID 会在启动时自动迁移。

## 推荐算法

全部在本机完成。实现见 `server/recommend.js` 与 `server/ml.js`。

### 反馈如何变成标签

收听时长按实际播放的音频计算，拖进度条不算。

| 行为 | 标签 |
| --- | --- |
| 点喜欢 | 正样本 `1` |
| 点 👎 不喜欢 | 负样本 `0` |
| 实际听了 ≥ 80%，或听了 ≥ 50% 后自然播完 | 正样本 `1` |
| 实际听了 ≥ 55% | 软标签 `0.7` |
| 听了 < 22% 且不到 25 秒 | 负样本 `0`（跳过） |
| 取消喜欢、其余 | 忽略 |

训练时按时间顺序回放事件，每条样本只用它**之前**的统计量，标签和未来的信息不会泄漏进特征。完播通常远多于跳过，所以两类样本会重新加权。只有正样本时，从没听过的歌手里随机抽几首当负样本。训练用固定随机种子，同样的记录总是得到同样的模型。

### 每首歌的特征向量（68 维）

| 段 | 维数 | 内容 |
| --- | --- | --- |
| 歌手哈希 | 32 | 歌手名 FNV-1a 哈希到带符号的槽 |
| 专辑哈希 | 16 | 专辑艺人 + 专辑名 |
| 流派哈希 | 8 | 有流派标签时使用 |
| 音频数值 | 4 | 时长、`log(1 + 时长)`、采样率、位深（降权） |
| 亲和 | 4 | 该歌手/专辑完播率、歌手播放占比、是否从未听过 |
| 行为 | 4 | 播放次数、跳过率、完播率、最近一次收听的时间衰减 |

去掉了「几点钟 / 是否周末」这类情境特征：线性模型里它们对所有候选曲都一样，不影响排序。

### 打分项

1. **逻辑回归**（SGD、L2、软标签、类别加权）→ `pLike`。
2. **序列**：按 30 分钟空档切 session。有种子曲时，`seqSim` 混合「听完种子后接着听这首」的次数（一阶转移）和 Item2Vec（16 维 skip-gram）与种子的相似度；没有种子时用 Item2Vec 与你完播过的歌的平均向量的相似度。
3. **内容**：内容向量与种子的余弦相似度。
4. **自己的常听**：`log(1 + 播放次数)` 归一化。反复听的歌是偏好，不是惩罚。

### 最终分数与多样性

```
score = 0.20 × pLike + 0.50 × seqSim + 0.15 × 常听 + 0.10 × contentSim
      − 0.30 × e^(−距上次收听的小时数 / 6)
      + 0.12（已喜欢）− 0.60（不喜欢）+ 0.02（从未听过）
```

再按 **MMR** 逐首挑选（`0.8 × score − 0.2 × 与已选曲的最大相似度`）。智能推荐模式通常取第一名，但有 15% 的概率从第 2–5 名里挑一首，避免总在同几首歌里打转。

### 离线评估

```bash
npm run eval
```

按时间切分听歌记录（前 80% 训练、后 20% 测试），统计 hit@10：以上一首为种子推荐的前 10 名里，是否包含你实际接着听完的那首。在一份真实记录（166 首、约 1500 条）上，当前模型为 18.9%；随机为 6.1%，「最常听」基线为 4.5%，「同歌手」基线为 6.4%；旧的打分公式为 3.0%。

## 隐私

- 没有账号、没有统计、没有远程推荐接口。所有数据只存在本机 `data/`。
- HTTP 服务默认绑定 **127.0.0.1**，曲库不会暴露到局域网；并拒绝 `Host` 不是本机的请求（防 DNS rebinding）。只有你明确要在可信网络里分享时，才设置 `HOST=0.0.0.0`。
- 能访问这个进程的人就可以调用 `/api/library` 和 `/api/stream` 列出并播放本地文件。除非有必要，请保持回环地址。
